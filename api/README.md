# Laravel 13 API

API платформы СТО для PHP 8.4 и PostgreSQL 15. Это самостоятельный backend: Vue-клиент находится в отдельном репозитории `msto`, а полный контракт — в [`API_EXAMPLES.md`](API_EXAMPLES.md).

## Основные каталоги

- `app/Http/Controllers` — HTTP-операции;
- `app/Http/Middleware` — JSON, авторизация, Origin и единый ответ;
- `app/Models` — Eloquent-модели нормализованных таблиц;
- `app/Services` — маршрут, права, импорт, каталоги и облачные файлы;
- `app/Console/Commands` — создание УК/организаций/пользователей и импорт автопарка;
- `database/migrations` — схема и PostgreSQL-комментарии;
- `tests/Feature/ApiTest.php` — интеграционные сценарии.

## Установка

```bash
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate --force
```

PostgreSQL должен быть версии 15. База, роль и схема `DB_SCHEMA` создаются заранее. В production используйте `APP_ENV=production`, `APP_DEBUG=false`, HTTPS и приватное S3-совместимое хранилище.

API использует токены Laravel Sanctum в заголовке `Authorization: Bearer`.
Для каждой учётной записи одновременно действует только один токен. Повторный
вход возвращает `SESSION_ACTIVE`; запрос с `force: true` завершает прежнюю
сессию и освобождает её блокировки.

## Начальная настройка

```bash
php artisan sto:tenant-create 'ООО "УК"'
php artisan sto:organization-create 'ООО "Тест"' --tenant=1 --kind=customer --vehicles='../imports/vehicles-test.xlsx'
php artisan sto:organization-create 'СТО-партнёр' --tenant=1 --kind=station --address='Адрес СТО'
php artisan sto:vehicle-contact-create LVUDB21B2RA042817 Иванов Иван '+7 999 123-45-67' --middle-name=Иванович
php artisan sto:time-norms-import 1 '../imports/time-norms.xlsx' --dry-run
php artisan sto:time-norms-import 1 '../imports/time-norms.xlsx'
php artisan sto:vehicle-reference-import --dry-run
php artisan sto:vehicle-reference-import
php artisan sto:test-cabinets-create --tenant=1
php artisan sto:users-import 1 '../imports/права доступа.xlsx' --dry-run
php artisan sto:users-import 1 '../imports/права доступа.xlsx'
php artisan sto:create-user NewUser 2 \
  --last-name=Иванов --first-name=Иван \
  --email=ivanov@example.ru --phone='+7 (999) 123 45 67'
```

Заявки этими командами не создаются. На чистой последовательности PostgreSQL первый `POST /api/requests` создаёт пустой документ `RP-000001`.

Контактные лица и водители хранятся в `organization_people`. Таблица
`vehicle_contacts` содержит только привязки выбранных записей к автомобилю.
API выбранного автомобиля возвращает их через
`GET /api/vehicles/{uuid}/contacts` и `GET /api/vehicles/{uuid}/drivers`.
Телефон принимается и возвращается в формате `+7 (ххх) ххх хх хх`.

Организации и пользователи разделены. Команды создания контура и организации,
а также справочники Заказчиков, СТО и УК не создают логины. Учётные записи
добавляются в справочнике «Пользователи», командой `sto:create-user` либо
импортом `sto:users-import`. Вид кабинета определяется организацией пользователя.
Непустая дата отзыва доступа или снятый признак активности блокируют вход и
завершают действующие сессии.

Импорт пользователей ожидает XLSX с колонками из файла «Права доступа».
Пустые ФИО и телефон заполняются воспроизводимыми тестовыми значениями, пустая
дата отзыва остаётся `NULL`. Учётные записи текущего контура, отсутствующие в
файле, сохраняются как ранее действовавшие, но блокируются. Владельцем старых
заявок и актов становится первый импортированный пользователь соответствующей
организации; исторические авторы событий не переписываются.

Файл норм времени должен быть в формате XLSX и содержать колонки `Работа` и `Норма, ч`. Необязательные колонки: `Модель автомобиля` и `Источник`. Дробная часть принимается с запятой или точкой. Пустая норма сохраняется как `NULL` для последующего ручного заполнения в ЛК УК. Повторный импорт обновляет норму для той же пары «работа + модель».

Команда `sto:vehicle-reference-import` загружает поставляемый с проектом
`database/data/vehicle_reference_ru_1990_2026.xlsx`: 411 марок и 52 983
технических варианта моделей, двигателей и поколений. По умолчанию команда
полностью синхронизирует справочник: отсутствующие в новой редакции варианты
становятся неактивными. Ключ `--append` оставляет такие записи активными.
Повторный запуск идемпотентен. Марка и модель ТС хранятся отдельно; выбранный
вариант связывается с `vehicle_models`.

В ЛК УК тот же импорт доступен через `POST /api/catalogs/time-norms/import`.
Изменения автомобилей, работ, норм, участников и запчастей сохраняются в
`catalog_change_events`; общий журнал действий возвращает
`GET /api/change-registry`. Пробег, контактные лица и водители ТС сохраняются
Заказчиком сразу. Остальные изменения ТС записываются в
`vehicle_change_requests` и применяются только после решения УК.

СТО принимает решение по времени через `POST /api/requests/{uuid}/station-decision`; комментарий необязателен. Время визита выбирается с шагом 30 минут в интервале с 08:00 до 22:00 по часовому поясу сервиса. Изменённые СТО работы и запчасти сначала согласует УК. Если УК корректирует смету, заявка возвращается в СТО с перечнем изменений; если принимает без правок — направляется Заказчику. После финального подтверждения Заказчика заявка ожидает ТС. СТО оформляет неизменяемый акт приёма через `POST /api/requests/{uuid}/acceptance-act`, после чего начинается работа и Заказчик с УК получают уведомления. Расчётное завершение определяется как время визита плюс 30 минут и сумма норм времени всех работ, затем нормализуется по времени и рабочим дням выбранной СТО.

Логины и пароли присутствуют только в справочнике «Пользователи». API всегда
возвращает вместо хеша пароля маску `••••••••••••`. Передача нового значения в
`PATCH /api/catalogs/{uuid}` для записи вида `users` заменяет пароль и завершает
действующие сессии. Исходный пароль не может быть прочитан из безопасного хеша.

Перед редактированием заявки или отдельной записи справочника клиент получает
временную блокировку через `POST /api/document-locks` и продлевает её
heartbeat-запросом. Списки справочников не блокируются. Попытка другого
пользователя изменить ту же запись возвращает HTTP 423
`DOCUMENT_LOCKED` с именем и логином владельца. Блокировки снимаются при
закрытии вкладки или выходе и автоматически истекают через
`DOCUMENT_LOCK_TTL_SECONDS`.

Собственные черновики этапа `0` удаляются по одному или группой через
`DELETE /api/requests/{uuid}` и `POST /api/requests/drafts/delete`. После
первой передачи по маршруту удаление документа запрещено. Черновик с созданным
чатом также нельзя удалить: переписка и файлы остаются вместе с заявкой.

Чат создаётся по кнопке рядом с «Сохранить» и доступен участникам заявки на
любом этапе. В сообщении сохраняются ID автора и его ФИО с ролью на момент
отправки. Все действующие пользователи организации Заказчика или назначенной
СТО участвуют в соответствующем чате; пользователи УК видят чаты заявок своего
контура после передачи черновика. Уведомления о непрочитанном считаются
отдельно для каждого пользователя и снимаются только после открытия чата и
отметки прочтения. История отдаётся страницами по 50 сообщений; файлы до 30 МБ
хранятся приватно и загружаются по запросу. Для PHP и входного прокси должны
быть настроены лимиты тела запроса, допускающие файл 30 МБ.

Для однократной очистки всех заявок и связанных документов с перезапуском
номера на `RP-000001` выполните:

```bash
php artisan sto:requests-purge --force
```

Команда не удаляет пользователей, организации, ТС и справочники.
Если хотя бы для одной заявки создан чат, команда откажет в очистке даже с
`--force`, чтобы не уничтожить историю переписки.

## Файлы

Объекты сохраняются приватно в S3; в PostgreSQL остаются метаданные, SHA-256 и привязка к статусу/событию. `GET /api/attachments/{uuid}/url` выдаёт ссылку на 5 минут. Если заданы `MEDIA_CDN_*`, API подписывает CloudFront-совместимую CDN-ссылку, иначе использует временную S3-ссылку.

## Тесты

Полный прогон:

```bash
vendor/bin/phpunit
```

Только Feature или Unit:

```bash
vendor/bin/phpunit --testsuite=Feature
vendor/bin/phpunit --testsuite=Unit
```

Один класс или один тест:

```bash
vendor/bin/phpunit --filter=AuthControllerTest
vendor/bin/phpunit --filter=test_login_returns_token_and_user_data
```

С покрытием (итоговые цифры):

```bash
XDEBUG_MODE=coverage vendor/bin/phpunit --coverage-text=php://stdout 2>&1 \
  | grep -E "Classes:|Methods:|Lines:"
```

Подробная шпаргалка по фильтрам, покрытию, CI и соглашениям — в
[`docs/testing.md`](docs/testing.md).

### Важно про метрику Methods

PCOV и Xdebug **занижают Methods** для контроллеров: Laravel вызывает их через
`$container->call()`, и coverage driver не помечает методы «вызванными», даже
если строки внутри исполнены. Lines и Classes считаются корректно.

**Для CI-гейта используем Classes и Lines**, Methods — информативно.

## Обновление 0.37.1

Поставщики создаются УК и СТО с реквизитами по организационно-правовой форме,
банковскими данными и несколькими контактами. Общие запчасти редактируются
обеими ролями; организация первого автора фиксируется автоматически.
Заказчик не получает поставщика и закупочную стоимость в ответах заявки и
рекомендаций. Видимость блока 04 появляется при первом согласовании Заказчиком.

Рекомендации одного автомобиля отображаются в двух общих таблицах; групповой
перенос в заявку атомарен. Применимость нормы выводится словами, подбор и расчёт
норм не менялись. Ручное добавление технического варианта ТС — единое окно
с подсказками и возможностью ввести новое значение.
Контракты: [API_EXAMPLES.md](API_EXAMPLES.md), схема: [docs/DATABASE.md](docs/DATABASE.md).
Для существующей установки применяется обычный `php artisan migrate --force`.
Команды очистки базы, повторного импорта справочников и сброса заявок не нужны.
