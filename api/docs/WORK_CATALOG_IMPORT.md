# Справочник работ и норм времени

## Назначение

Новая редакция справочника загружается одним файлом XLSX с листами
`Работы` и `Нормы времени`. Сначала API выполняет полную сверку без изменения
БД. Применение разрешено только для файла без ошибок и выполняется одной
транзакцией PostgreSQL.

Справочник из поставки сформирован исключительно из файла
`Справочник_работ_автосервиса 01102026(1).xlsx`. В исходнике нет нормо-часов,
поэтому все 1 648 записей норм имеют `NULL`, а не предполагаемое значение.

## Лист «Работы»

| Колонка | Правило |
|---|---|
| Код работы | Постоянный код `AA-BBBBB`, уникальный в активном справочнике |
| Код группы | Две латинские буквы; совпадают с началом кода работы |
| Группа | Значение из закрытого перечня `config/sto.php` |
| Наименование работы | Формат «деталь или система - действие» |
| ТО | `Да` или `Нет` |
| Активна | `Да` или `Нет` |
| Исходная строка | Положительное целое число или пусто |
| Источник | Наименование файла, документа или другое подтверждение |

## Лист «Нормы времени»

| Колонка | Правило |
|---|---|
| norm_id | Постоянный идентификатор `AA-BBBBB-NNN` |
| Код работы | Должен существовать на листе «Работы» |
| Норма времени, ч | Положительное число или пусто (`NULL`) |
| VIN | Существующее ТС; 17 допустимых символов |
| Марка | Существующая активная запись `vehicle_makes` |
| Модель | Существующая активная модель выбранной марки |
| Поколение | Существующее поколение выбранной модели |
| Индекс двигателя | Вариант двигателя выбранной модели/поколения |
| Трансмиссия | Запись закрытого справочника трансмиссий |
| Привод | Запись закрытого справочника приводов |
| Код модификации | Текстовый типизированный признак модификации |
| Активна | `Да` или `Нет` |
| Источник | Подтверждающий источник нормы |

Пустой признак применимости означает «любое значение». Признаки задаются
последовательно: марка; марка и модель; марка, модель и поколение; затем при
необходимости двигатель, трансмиссия, привод и код модификации. Модель
проверяется на принадлежность марке, поколение — модели, двигатель — модели и,
при наличии связи, поколению.

Миграция переносит уже имеющиеся `body_code`, `engine_index`, `transmission` и
`drive_type` из `vehicle_models` в типизированные справочники и связывает с
ними существующие автомобили. Новые записи применимости используют только
внешние ключи; строковый составной код остаётся представлением для интерфейса.

## Выбор нормы

API отбирает только активные правила, все заполненные признаки которых
совпадают с автомобилем. Приоритет от наиболее узкого правила:

1. конкретный автомобиль (VIN);
2. поколение с максимальным числом совпавших уточняющих признаков;
3. поколение без уточняющих признаков;
4. марка и модель;
5. марка;
6. общая норма.

Для уровня поколения более детализированное правило имеет приоритет над менее
детализированным. Если два совпавших правила имеют
одинаковый уровень и одинаковую детализацию, результат — `conflict`; случайный
выбор запрещён. Составной код применимости формируется только для интерфейса.

## Стоимость работы

Стоимость позиции фиксируется при сохранении заявки:

```text
стоимость позиции = норма времени × vehicles.labor_hour_rate × количество
```

Например: `1,25 ч × 2 400,00 ₽/ч × 2 = 6 000,00 ₽`.

В `request_works` сохраняются снимки кода и наименования работы, `norm_id`,
нормы, ставки, количества и суммы. `labor_rate_coefficient` в формуле не
участвует. Если норма или ставка отсутствует, сумма остаётся `NULL`; заявка не
может пройти согласование как позиция с `0 ₽`.

Ручная норма действует только в данной заявке. Для неё обязательны положительное
значение и `normOverrideReason`; запись `time_norms` не меняется.

## Проверки перед импортом

Сверка возвращает номер листа, строки и ячейки для каждого нарушения:

- формат и уникальность кода работы;
- соответствие кода работы коду группы;
- закрытый перечень групп;
- формат и смысловая уникальность наименования;
- значения логических полей;
- наличие хотя бы одной записи нормы для каждой работы;
- формат и уникальность `norm_id`;
- ссылка нормы на работу из того же файла;
- положительное значение нормы либо пустое значение;
- корректность VIN и существование ТС в тенанте;
- существование марки, модели, поколения, двигателя, трансмиссии и привода;
- принадлежность модели марке, поколения модели, двигателя модели/поколению;
- соответствие всех указанных признаков конкретному VIN;
- последовательность признаков применимости от марки до модификации;
- пересекающиеся правила без однозначного приоритета.

Не более 1 000 ошибок возвращается за одну сверку. Пустые нормы возвращаются
отдельным предупреждением и импортируются как `NULL`.

## Атомарная замена и история

Текущий справочник не объединяется с загружаемым и не переносится в новую
активную редакцию. Это соответствует запуску без действующих документов,
ссылающихся на прежние работы. Архивирование оставлено как техническая защита
целостности внешних ключей на случай, если такая ссылка всё же обнаружится.

При применении импорта блокируется запись тенанта. В одной транзакции:

1. создаётся пакет `work_catalog_imports`;
2. прежние активные работы и нормы переводятся в архив;
3. создаётся новая версия работ и норм;
4. пакет получает статус `applied`.

При любой ошибке откатываются все четыре действия. Старые записи не удаляются,
поэтому внешние ключи исторических заявок и согласованные снимки стоимости
сохраняются.

## API

### Предварительная сверка

```http
POST /api/catalogs/work-catalog/import/preview
Authorization: Bearer <token УК>
Content-Type: multipart/form-data

file=@work-catalog.xlsx
```

Ответ содержит `checksum`, `canApply`, `summary`, `errors`, `warnings`,
нормализованные `works` и `norms`.

### Применение проверенного файла

```http
POST /api/catalogs/work-catalog/import/apply
Authorization: Bearer <token УК>
Content-Type: multipart/form-data

file=@work-catalog.xlsx
checksum=<checksum из preview>
```

Файл повторно читается и проверяется. Если его контрольная сумма изменилась,
API отвечает `409 IMPORT_FILE_CHANGED`.

### Подбор нормы для строки заявки

```http
GET /api/time-norms/resolve?workTypeId=<uuid>&vehicleId=<uuid>&quantity=2
Authorization: Bearer <token>
```

Ответ содержит `status` (`selected`, `missing`, `conflict`), выбранную норму,
область применимости, конфликты, ставку автомобиля и рассчитанную сумму.
