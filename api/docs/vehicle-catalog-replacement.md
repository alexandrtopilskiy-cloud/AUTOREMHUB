# AUTOREMHUB ver. 0.32.1 — замена тестового каталога ТС

Основа: API main 3d921972627e0cc3c4acdc1145fbd4f379576d8e; Front main 16f7d05e6f4cb28fd318deecb03038a87d6a9b2c. Ветка обоих bundle: feature/vehicle-catalog-replacement-20261004.

Архив объединяет все неопубликованные изменения 0.31.1 и обновление каталога от 05.10.2026. Применяется сразу поверх 0.30.1; отдельно устанавливать 0.31.1 не требуется. Старый архив 0.31.1 для этой установки не используйте.

## Что изменено

Последовательный выбор: марка → модель → поколение (период и кузов) → тип двигателя → индекс → мощность → объём → трансмиссия → привод. Изменение предыдущего параметра сбрасывает последующие. Неоднозначный вариант не выбирается автоматически. Электрокарам разрешён пустой объём. Технические данные ТС закреплены за выбранной записью внутреннего каталога.

Импорт нового Excel содержит 11118 строк данных: 11045 уникальных записей по 10 маркам и 73 точных повтора. В командном импорте точные повторы пропускаются с отчётом skippedDuplicates; противоречащие записи с одинаковым техническим ключом отклоняются. Для каждой связки марка — модель — кузов проверен единый период выпуска. «Нет данных» и «Не применимо» преобразуются в пустые значения соответствующих полей. Исходный XLSX включён в API bundle в database/data/vehicle_reference_20261005.xlsx.

Сохранены ограничения ролей и согласование изменений Заказчика. Контакты, водители и разрешённое изменение пробега сохраняются напрямую. Три тарифа: общий (прежний labor_hour_rate), официальный и прочий. В заявке УК выбирает тариф; выбранная ставка фиксируется в позиции. Формула прежняя: норма × ставка × количество, коэффициент не применяется. Незаполненный тариф не подменяется общим. Алгоритм подбора норм времени не изменён.

При завершении заявки пробег ТС увеличивается только если новый больше текущего; фиксируется время завершения документа. Незавершённые заявки не используются как предыдущий пробег.

## Применение bundle

Распакуйте архив. Выполните в каждом существующем репозитории отдельно (используйте абсолютный путь к нужному bundle).

```bash
git switch main
git pull --ff-only
git bundle verify /absolute/path/autoremhub-api-v0.32.1.bundle
git fetch /absolute/path/autoremhub-api-v0.32.1.bundle feature/vehicle-catalog-replacement-20261004:feature/vehicle-catalog-replacement-20261004
git merge --ff-only feature/vehicle-catalog-replacement-20261004
```

В Front замените имя файла на autoremhub-front-v0.32.1.bundle. Если main после указанной основы изменился и fast-forward невозможен, согласуйте изменения обычным merge/rebase; не используйте принудительный reset.

## Развёртывание и очистка

Команда очистки необратимо удаляет ВСЕ заявки на ремонт и ТС Заказчиков с зависимыми документами, контактными связями и заявками изменения ТС. Организации, пользователи, справочник работ, контактные лица и водители остаются. Нормы для конкретных удалённых ТС архивируются; нормы с отсутствующими в новом каталоге техническими ссылками деактивируются. Общие нормы и нормы для сохраняющихся марок остаются. Старые записи технического каталога сохраняются неактивными. Файлы в CDN физически не удаляются этой командой.

Перед очисткой сделайте проверяемую резервную копию PostgreSQL и остановите фоновые задания/воркеры, способные писать в эти таблицы. Пример резервной копии (подставьте свои параметры):

```bash
pg_dump -h HOST -U USER -d DATABASE -Fc -f before-v0.32.1.dump
```

В API:

```bash
composer install --no-dev --optimize-autoloader
php artisan down
php artisan migrate --force
php artisan sto:replace-test-vehicle-catalog database/data/vehicle_reference_20261005.xlsx
php artisan sto:replace-test-vehicle-catalog database/data/vehicle_reference_20261005.xlsx --apply
php artisan optimize:clear
```

Первая команда замены только проверяет файл, вторая атомарно очищает тестовые данные и заменяет каталог. При ошибке транзакция откатывается. Затем в Front:

```bash
npm ci
npm run build
```

Опубликуйте dist вашим существующим способом, затем в API выполните `php artisan up` и возобновите воркеры. Восстановление удалённых данных возможно только из резервной копии БД; откат Git их не возвращает.

Будущее добавление записей без замены каталога:

```bash
php artisan sto:vehicle-reference-import /absolute/path/additions.xlsx --dry-run --append
php artisan sto:vehicle-reference-import /absolute/path/additions.xlsx --append
```

## API

GET /api/vehicle-reference/selection?makeId=UUID&step=model — варианты следующего шага; последовательные шаги: model, generation, engineType, engineIndex, hp, volume, transm, drive. Предыдущие значения передаются в filters[model], filters[generation] и т. д. Пустой технический признак представлен токеном __unknown__. Ответ содержит options и после однозначного последнего выбора variant.

ТС: vehicleModelId связывает запись с каталогом; technicalReference содержит его признаки; engineVolumeLiters — объём в литрах. УК доступны laborHourRate (общий), laborHourRateOfficial, laborHourRateOther; пустые тарифы — null. Заявка: laborRateType = general | official | other. Подбор нормы принимает этот же необязательный атрибут. Выбор норм по применимости не меняется.
