# Импорт справочников из Excel

Версия: 0.28.1.

Импорт доступен только пользователям ЛК УК. Кнопка **«Импорт из Excel»**
открывает один мастер из четырёх последовательных этапов:

1. скачать индивидуальный шаблон выбранного справочника;
2. заполнить и загрузить XLSX;
3. проверить файл и импортировать его;
4. получить подтверждение с количеством проверенных строк и созданных записей.

Импорт выполняется только в режиме добавления. Существующие записи не
обновляются и не удаляются. Операция атомарна: если найдена хотя бы одна
ошибка, импортируется **ноль** строк. В таблице конфликтов выводятся номер
строки Excel, адрес ячейки, столбец, исходное значение и причина.

Реестры «Согласование изменений ТС» и «Реестр изменений» импортировать нельзя:
это системные журналы, записи в которых создаются только бизнес-процессами.

## Общие проверки файла

- доступ разрешён только роли `manager`;
- принимается только файл с расширением `.xlsx` размером до 30 МБ;
- один файл может содержать не более 100 000 непустых строк данных;
- в книге должен быть лист со строкой заголовков из актуального шаблона;
- все столбцы шаблона обязательны, даже когда значения в них необязательны;
- неизвестные, удалённые и повторяющиеся заголовки считаются конфликтом;
- полностью пустые строки пропускаются;
- файл без строк данных отклоняется;
- значения проверяются теми же правилами, что и ручное создание записи;
- связи разрешаются только внутри текущего контура (tenant);
- повтор записи в самом XLSX определяется так же, как повтор с записью БД;
- при конфликте транзакция откатывается целиком, включая журнал изменений.

Допустимые логические значения: `Да`, `Нет`, `1`, `0`, `true`, `false`,
`yes`, `no`. Пустое значение получает значение по умолчанию, указанное ниже.
В списках несколько значений разделяются точкой с запятой. Даты принимаются
в формате `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД` либо как дата Excel.

## Проверки по справочникам

### Справочник ТС Заказчиков (`vehicles`)

Столбцы: наименование заказчика, марка, модель, поколение/кузов, VIN,
госномер, год выпуска, предыдущий пробег и его дата, стоимость нормо/часа,
поправочный коэффициент, телефоны контактных лиц и водителей.

Проверки:

- Заказчик должен существовать как организация типа «Заказчик»;
- марка и модель должны существовать и быть активными во внутреннем
  справочнике ТС;
- если для марки и модели найдено несколько поколений, обязательно заполнить
  «Поколение / кузов»; год выпуска дополнительно ограничивает подходящие
  варианты;
- VIN обязателен, содержит ровно 17 латинских букв/цифр без `I`, `O`, `Q` и
  не должен существовать в БД либо повторяться в файле;
- госномер — до 30 букв, цифр, пробелов или дефисов;
- год выпуска — целое число от 1900 до 2100;
- пробег — целое число от 0 до 999 999 999;
- стоимость нормо/часа — от 0 до 1 000 000 000, до двух знаков после запятой;
- коэффициент — от 0,001 до 100, до трёх знаков; пустое значение равно 1,000;
- каждый указанный телефон должен быть корректным российским номером и
  существовать в соответствующем справочнике этой же организации.

### Справочник ТС (марки, модели) (`vehicleModels`)

Столбцы: марка, модель, модельный год от/до, индекс двигателя,
поколение/кузов, мощность, трансмиссия, привод и тип двигателя.

Проверки:

- марка и модель обязательны;
- годы — от 1900 до 2100, конечный год не меньше начального;
- мощность — от 0,1 до 3000,0 л.с., не более одного знака после запятой;
- трансмиссия: `МКПП`, `РКПП`, `АКПП`, `CVT`, `электро` либо пусто;
- привод: `передний`, `задний`, `полный` либо пусто;
- двигатель: `Бензин`, `дизель`, `гибрид`, `электро` либо пусто;
- комбинация всех признаков варианта модели (fingerprint) должна быть новой.

### Водители (`drivers`) и Контактные лица (`contactPersons`)

Столбцы: наименование заказчика, фамилия, имя, отчество, сотовый телефон.

Проверки:

- организация должна существовать как Заказчик текущего контура;
- фамилия, имя и телефон обязательны;
- телефон нормализуется к `+7XXXXXXXXXX`; допустим ввод
  `+7 (ххх) ххх хх хх` или `8xxxxxxxxxx`;
- активная запись с тем же телефоном, типом лица и организацией не допускается.

### Справочник Работ (`workTypes`)

Столбцы: наименование работы, группа, ТО, активна, применимость, марка ТС,
модель ТС, норма времени и источник.

Проверки:

- название обязательно и не должно существовать в справочнике;
- группа выбирается из закрытого перечня проекта;
- пустые значения «ТО» и «Активна» означают соответственно `Нет` и `Да`;
- применимость должна существовать и быть активной; пустое значение —
  `Общая`;
- для применимости `По авто` обязательна марка и/или модель из внутреннего
  справочника ТС;
- при иной применимости поля марки и модели должны быть пустыми;
- норма времени может быть пустой либо числом от 0,001 до 100 000 часов с
  точностью до трёх знаков;
- строки с одинаковым названием объединяются в одну Работу с несколькими
  нормами; группа и признаки `ТО`/`Активна` во всех таких строках должны
  совпадать;
- одинаковые нормы применимости внутри одной Работы не допускаются.

### Применимости норм (`normApplicabilities`)

Столбцы: применимость, активна.

Проверки:

- название обязательно и уникально без учёта регистра;
- пустое значение «Активна» означает `Да`;
- системные и ранее созданные применимости повторно не добавляются.

### Справочник запчастей (`parts`)

Столбцы: наименование, артикул, производитель, единица измерения, активна.

Проверки:

- наименование обязательно;
- единица выбирается из закрытого перечня проекта (`шт.`, `ед.`, `компл.`,
  `набор`, `пара`, `упак.`, `л`, `мл`, `кг`, `г`, `м`, `см`, `м²`, `рулон`,
  `баллон`, `канистра`);
- пустое значение «Активна» означает `Да`;
- при заполненном артикуле уникальна пара «артикул + производитель»;
- при пустом артикуле уникальна пара «наименование + производитель».

### Справочник Заказчики (`customers`) и Справочник УК (`managers`)

Столбцы: наименование, краткое наименование, ИНН, КПП, ОГРН, юридический,
фактический и почтовый адреса, руководитель, контакт, телефон, e-mail, банк,
БИК, расчётный и корреспондентский счета, система налогообложения, НДС.

Проверки:

- наименование обязательно и уникально внутри типа организации;
- ИНН — 10 или 12 цифр и не должен повторяться внутри типа организации;
- КПП и БИК — 9 цифр;
- ОГРН — 13 или 15 цифр;
- расчётный и корреспондентский счета — по 20 цифр;
- e-mail проверяется как адрес электронной почты;
- ставка НДС — число от 0 до 100.

### Справочник СТО (`stations`)

Содержит все реквизиты организации, адрес СТО, время и дни работы,
количественные характеристики, перечень возможностей и текстовые признаки
чек-листа СТО.

Проверки:

- применяются все проверки реквизитов организации из предыдущего раздела;
- начало и окончание работы обязательны в формате `ЧЧ:ММ`;
- окончание должно быть позже начала;
- рабочие дни обязательны; допустимы `Пн.;Вт.;Ср.;Чт.;Пт.;Сб.;Вс.` либо
  числа `1;2;3;4;5;6;7`;
- количественные параметры — целые числа от 0 до 10 000, пусто означает 0;
- признаки возможностей — логические значения, пусто означает `Нет`;
- «Активна» по умолчанию означает `Да`;
- наименование или ИНН не должны повторять существующую СТО.

### Справочник Пользователи (`users`)

Столбцы: ФИО, e-mail, логин, пароль, мобильный телефон, организация, дата
регистрации, дата отзыва доступа, активность и права через `;`.

Проверки:

- организация должна существовать в текущем контуре; роль пользователя
  определяется её типом;
- фамилия, имя, e-mail, логин, пароль и телефон обязательны;
- логин и e-mail не должны существовать в БД либо повторяться в файле;
- пароль содержит от 12 до 72 символов;
- телефон — российский номер в формате `+7 (ххх) ххх хх хх`;
- даты должны быть корректными; при заполненной дате отзыва вход блокируется;
- пустое значение «Активен» означает `Да`;
- права должны входить в закрытый перечень API; если поле пусто, применяются
  стандартные права роли организации.

## API

Скачать шаблон:

```http
GET /api/catalogs/{kind}/import/template
Authorization: Bearer <token УК>
```

Проверить и импортировать:

```http
POST /api/catalogs/{kind}/import
Authorization: Bearer <token УК>
Content-Type: multipart/form-data

file=<catalog.xlsx>
```

Успешный ответ — HTTP 201:

```json
{
  "result": {
    "success": true,
    "catalog": "vehicles",
    "rows": 25,
    "imported": 25,
    "conflicts": []
  }
}
```

При конфликте — HTTP 422, импорт всегда равен нулю:

```json
{
  "error": {
    "code": "IMPORT_CONFLICTS",
    "message": "В XLSX найдены конфликты. Данные не импортированы"
  },
  "result": {
    "success": false,
    "catalog": "vehicles",
    "rows": 25,
    "imported": 0,
    "conflicts": [
      {
        "catalog": "vehicles",
        "row": 7,
        "cell": "E7",
        "column": "VIN",
        "value": "XTA00000000000001",
        "message": "Такая запись уже существует в справочнике"
      }
    ]
  }
}
```
