## Общие принципы

- Контракт API **не меняется**. Инфраструктурные изменения не ломают фронтенд.
- Каждый подэтап — отдельный PR или отдельная задача.
- Все изменения на проде — через постепенный rollout, без «большого взрыва».
- Метрики до и после каждого этапа фиксируются в комментарии к PR.
- Мониторинг — до оптимизации. Без цифр любые изменения — гадание.

### Этап 4. Yandex Object Storage (вложения)

**Цель:** убрать файлы с локального диска. Снять нагрузку с `/srv/msto_api/storage/app/media`, упростить доступ при горизонтальном масштабировании, избавиться от ручного бэкапа файлов.

**Условие старта:** Этап 3 завершён (сервер расширен, OPcache включён), baseline зафиксирован.

**Почему до Redis:** хранилище — это про диск и доступ, а не про кеш. Если начать с Redis и прогреть кеш, локальный диск всё равно останется узким местом при росте объёма вложений. Плюс переезд на S3 — это изменение, которое затрагивает код загрузки/скачивания, и лучше сделать его до того, как добавлять кеш поверх.

- [ ] 4.1. Подготовка в Yandex Cloud:
    - [ ] Создать бакет в Object Storage (например, `msto-attachments`)
    - [ ] Выбрать регион `ru-central1`
    - [ ] Настроить версионирование (опционально, но полезно для восстановления)
    - [ ] Создать сервисный аккаунт с ролью `storage.editor` (или уже́, если нужно)
    - [ ] Сгенерировать статический ключ доступа (Access Key ID + Secret)
    - [ ] Сохранить ключи в защищённом хранилище (не в git)
- [ ] 4.2. Настройка Laravel:
    - [ ] Добавить диск `yandex` в `config/filesystems.php` через S3-драйвер:
        ```php
        'yandex' => [
            'driver' => 's3',
            'key' => env('YANDEX_STORAGE_KEY'),
            'secret' => env('YANDEX_STORAGE_SECRET'),
            'region' => env('YANDEX_STORAGE_REGION', 'ru-central1'),
            'bucket' => env('YANDEX_STORAGE_BUCKET'),
            'endpoint' => env('YANDEX_STORAGE_ENDPOINT', 'https://storage.yandexcloud.net'),
            'use_path_style_endpoint' => false,
        ```

    - [ ] Проверить, что `Storage::disk('yandex')->put(...)` и `->get(...)` работают

    - [ ] Зафиксировать количество файлов до и после

**Замечания:**
- **Не делайте бакет публичным.** Отдача файлов через `AttachmentController::download` сохраняет контроль доступа. Presigned URL — альтернатива для прямого скачивания.
- **Проверьте консистентность `Attachment::disk` в БД.** Если старые записи хранят `media` как имя диска, а вы переименовали диск в `yandex`, нужно либо оставить алиас `media` → S3, либо мигрировать значения.
- **CORS нужен, только если фронт качает напрямую из S3.** Если всё идёт через Laravel-контроллер, CORS не требуется.
- **Стоимость Object Storage** для вашего объёма — копейки (в пределах 100 ГБ исходящего трафика бесплатно ежемесячно).
