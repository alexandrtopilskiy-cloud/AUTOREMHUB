# Vue 3 frontend — Options API

Только клиентская часть платформы. Здесь нет mock API, БД, PHP/Node-сервера и предзаполненных заявок. Все компоненты используют Vue 3 Options API (`data`, `computed`, `methods`, lifecycle hooks).

## Структура

- `src/api/client.js` — HTTP, Bearer-аутентификация, тайм-ауты и ошибки;
- `src/api/marketplace.js` — адаптер всех маршрутов API;
- `src/stores/requestStore.js` — состояние, ручное сохранение и конфликты revision;
- `src/features/auth` — вход;
- `src/features/requests` — заявка, автомобиль, работы, запчасти, файлы, переходы и оплата;
- `src/features/catalogs` — справочники ТС, участников, работ, запчастей и согласование изменений;
- `src/features/vehicles` — статистика ТО и работ;
- `src/data` — подписи маршрута и отображения;
- `public/favicon.ico` и `public/favicon.svg` — favicon;
- `tests` — проверки store, HTTP и SSR-компонентов.

## Подключение

```bash
cp .env.example .env
npm ci
npm test
npm run build
```

Укажите в `.env`:

```dotenv
VITE_API_BASE_URL=/api
VITE_SERVICE_TIMEZONE=Europe/Moscow
```

Готовые файлы находятся в `dist/`. Node.js 24.x нужен только для сборки; production Node-сервер не требуется. Полный контракт backend находится в `../API_EXAMPLES.md`.

Права на поля и действия приходят в `request.permissions`; скрытие кнопок в
клиенте не заменяет серверную проверку. Токен хранится в `sessionStorage`
текущей вкладки, а в `localStorage` — только ширина и свёрнутость трёх
областей. При уже активной сессии форма входа предлагает отменить вход либо
завершить прежнюю сессию. Документы и справочники не сохраняются вне API.

Изменения заявки отправляются в API только по кнопке «Сохранить». При закрытии виртуальной вкладки с изменённой заявкой интерфейс предлагает сохранить или отбросить изменения.

Заказчик видит в меню только ТС своей организации, а также отдельные
справочники «Контактные лица» и «Водители». Связанные лица выбираются в строках
таблицы, а кнопка «Добавить ещё» создаёт следующую строку. Телефон вводится по
маске `+7 (ххх) ххх хх хх`. Водители, контактные лица и пробег применяются
сразу по кнопке «Сохранить»; остальные изменения, создание и удаление ТС
требуют акцепта УК. Новый автомобиль до акцепта не появляется в списке.

В ЛК УК автомобиль и пробег заявки отображаются без возможности изменения, а работы и запчасти доступны для добавления и удаления. Стоимость нормо/часа берётся по VIN из справочника ТС. Переход УК не требует вложений; комментарий к решению необязателен. Раздел «Справочники» содержит все ТС, работы, неизменяемый после создания каталог запчастей, Заказчиков, СТО, УК, Пользователей, очередь согласования ТС и общий реестр действий. Для каждого столбца предусмотрен отдельный фильтр. Нормы времени можно импортировать из XLSX; пустое значение отображается до ручного заполнения УК.

В справочнике ТС марка и модель разделены. Оба значения выбираются через
поиск по начальным символам, причём модель доступна только после выбора марки.
Недостающий вариант создаётся в двухшаговом диалоге с техническими признаками.
Логины, пароли, ФИО, телефон, даты регистрации/отзыва и права находятся только
в справочнике «Пользователи». Запись связывается с организацией Заказчика, СТО
или УК; эта связь определяет вид кабинета. Справочник доступен только ЛК УК.
Пароль всегда показан маской, а непустая дата отзыва блокирует вход. В правом
верхнем углу отображаются ФИО вошедшего пользователя и его организация.

Во всех редактируемых справочниках УК доступен единый четырёхшаговый импорт из
Excel: скачивание индивидуального шаблона, загрузка заполненного XLSX, проверка
и результат. Конфликты показываются с номером строки и адресом ячейки; при
наличии хотя бы одного конфликта API не добавляет ни одной строки.

Выбор даты и времени визита выполняется в одном компактном раскрывающемся поле
в 24-часовом формате с шагом 30 минут. Доступное время — с 08:00 до 22:00;
нельзя выбрать момент раньше текущего времени плюс 30 минут. Значение
фиксируется самим выбором, отдельной кнопки «ОК» нет.

В ЛК СТО автомобиль и пробег доступны только для просмотра, организация
Заказчика скрыта. На этапах согласования СТО может дополнять работы и запчасти;
эти изменения проходят согласование УК. Подтверждённое время сначала совпадает
с желаемым. СТО подтверждает его, предлагает другое время в диалоге либо
отказывается от заявки. Расчётное завершение отображается только для чтения и
вычисляется API как время визита + 30 минут + сумма норм времени работ. При
переносе Заказчик получает уведомление, принимает время СТО либо предлагает
своё, после чего заявка возвращается в УК. Комментарий к решению необязателен.
Заявки, справочники и уведомления обновляются автоматически без перезагрузки
страницы; прочитанное уведомление Заказчика удаляется.

Блокировка удерживается только для редактируемой заявки или конкретной записи
справочника. Остальные записи справочника остаются доступными; заявки вне
текущего кабинета маршрута открываются только для просмотра. Второй
пользователь получает сообщение с логином владельца занятой записи.

Собственные черновики, ни разу не переданные по маршруту, можно удалить по
одному либо группой. Первичная передача Заказчиком в УК выполняется без
диалога: комментарий и вложения остаются необязательными.

## Справочник работ и нормы времени (ver. 0.30.1)

Импорт справочника работ в ЛК УК использует отдельный безопасный сценарий:
загрузка XLSX с листами `Работы` и `Нормы времени`, предварительная сверка,
просмотр принятых записей и конфликтов, затем атомарное применение по
контрольной сумме файла. Предыдущий активный каталог не смешивается с новым.

При выборе работы в заявке интерфейс запрашивает у API наиболее узкую норму
для выбранного автомобиля. Стоимость строки рассчитывается как
`норма времени × стоимость нормо-часа ТС × количество`. Ручная норма требует
причину и действует только в текущей заявке; пустая справочная норма не
превращается в стоимость `0 ₽`.

Норму можно ограничить конкретным VIN либо сочетанием марки, модели,
поколения, двигателя, трансмиссии, привода и кода модификации. Удаление нормы
в редакторе применяется общей кнопкой «Сохранить» и архивирует запись, поэтому
согласованные исторические заявки сохраняют исходные значения.

Иерархия применимости допускает отдельные уровни: марка; марка и модель;
марка, модель и поколение; далее — уточнение по двигателю, трансмиссии, приводу
и коду модификации. Более детализированная подходящая норма имеет приоритет.
